2. Setting up Inter-Process Communication (IPC)
Electron keeps your UI (Renderer process) isolated from the operating system (Main process) for security. You'll want to set up an IPC bridge in your preload.ts file:
```ts
// src/preload.ts
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('electronAPI', {
  sendMessage: (message: string) => ipcRenderer.send('to-main', message)
});
```

3. Integrating Styling
If you want to use Tailwind CSS, you can initialize it normally via npm, but you must ensure your content array in tailwind.config.js points to your renderer files (e.g., ./index.html, ./src/**/*.{js,ts,jsx,tsx}) so it purges properly.

4. Fixing VS Code Debugging
If you try to set breakpoints in VS Code right now, you might notice they don't bind. A common gotcha with the Vite template is needing to manually enable sourcemaps in your config:
```ts
// vite.main.config.ts
export default defineConfig({
  build: {
    sourcemap: true,
  },
});
```

> I'd like to "Adding virtual scrolling to handle large sets of data smoothly"

Virtual scrolling keeps your Electron app performing at 60 FPS even with 100,000 items.
Instead of creating thousands of DOM elements (which hogs memory and causes lag), virtual scrolling renders only the items visible on the screen,
plus a tiny buffer.

As the user scrolls, we rapidly reuse or swap the content of those few DOM elements and shift their positions.

Here is how to implement a high-performance fixed-height virtual scroll using your existing vanilla TypeScript setup.

Step 1: Update the CSS Layout
We need a structure where an outer container handles the actual scroll bar, and an inner container artificially stretches to the height that the full list would be.

```css
/* src/index.css */
.item-list {
  position: relative; /* Crucial for absolute positioning of rows */
  list-style: none;
  margin: 0;
  padding: 0;
  overflow-y: auto;   /* This will handle the scrolling */
  flex-grow: 1;
  height: 100%;       /* Fill the window space */
}

/* The phantom element that stretches the scrollbar */
.virtual-runway {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  visibility: hidden; /* Invisible, just there for height */
}

.list-item {
  position: absolute; /* Positioned precisely via JavaScript transform */
  left: 0;
  width: 100%;
  box-sizing: border-box;
  display: flex;
  justify-content: space-between;
```

Step 2: Implement the Virtual Scroll Engine
Replace your src/renderer.ts script with this high-performance rendering loop. It recalculates which items are visible during every scroll event using standard math.
```ts
// src/renderer.ts
import { ListItem } from './interface';

// 1. Config Variables
const ITEM_HEIGHT = 72;   /* Must match the CSS height perfectly */
const BUFFER_ITEMS = 5;   /* Extra elements above/below viewport to prevent flickering */

// 2. DOM Elements
const listContainer = document.getElementById('list-container') as HTMLUListElement;

// Create the phantom element to enforce scrollbar size
const runway = document.createElement('div');
runway.className = 'virtual-runway';
listContainer.appendChild(runway);

// Cache for our loaded dataset
let allItems: ListItem[] = [];

// 3. Item Component Builder
function createListItemElement(item: ListItem): HTMLLIElement {
  const li = document.createElement('li');
  li.className = 'list-item';
  li.innerHTML = `
    <div class="item-content">
      <span class="item-title">${item.title}</span>
      <p class="item-desc">${item.description}</p>
    </div>
    <button class="delete-btn">Complete</button>
  `;

  li.querySelector('.delete-btn')?.addEventListener('click', (e) => {
    e.stopPropagation();
    // Remove from our memory array
    allItems = allItems.filter(i => i.id !== item.id);
    // Trigger structural refresh
    renderVirtualList();
  });

  return li;
}

// 4. Core Rendering Engine
function renderVirtualList() {
  const scrollTop = listContainer.scrollTop;
  const containerHeight = listContainer.clientHeight;
  const totalItems = allItems.length;

  // Set total height so the native scrollbar behaves correctly
  runway.style.height = `${totalItems * ITEM_HEIGHT}px`;

  // Calculate indices of items currently visible in viewport
  let startIndex = Math.floor(scrollTop / ITEM_HEIGHT) - BUFFER_ITEMS;
  let endIndex = Math.ceil((scrollTop + containerHeight) / ITEM_HEIGHT) + BUFFER_ITEMS;

  // Clamp boundaries to valid array lengths
  startIndex = Math.max(0, startIndex);
  endIndex = Math.min(totalItems - 1, endIndex);

  // Clear everything except the runway
  const elementsToRemove = listContainer.querySelectorAll('.list-item');
  elementsToRemove.forEach(el => el.remove());

  // Render only the visible subset
  const fragment = document.createDocumentFragment();
  for (let i = startIndex; i <= endIndex; i++) {
    const item = allItems[i];
    if (!item) continue;

    const itemEl = createListItemElement(item);
    
    // Position the item exactly where it belongs in the long timeline
    const topPosition = i * ITEM_HEIGHT;
    itemEl.style.transform = `translateY(${topPosition}px)`;
    
    fragment.appendChild(itemEl);
  }
  
  listContainer.appendChild(fragment);
}

// 5. Setup Listeners and Initializers
async function initList() {
  try {
    // Fetch dataset from main process (mocking 50,000 items)
    allItems = await window.api.fetchListItems();
    
    // Listen for scrolling
    listContainer.addEventListener('scroll', () => {
      // requestAnimationFrame guarantees calculation matches screen refresh rate (no stutter)
      requestAnimationFrame(renderVirtualList);
    });

    // Handle window resizing dynamically
    window.addEventListener('resize', renderVirtualList);

    // Initial render pass
    renderVirtualList();
  } catch (error) {
    console.error('Failed to load list items:', error);
  }
}

initList();
```

> Should the scroll event listener be passive?
> 
> // Listen for scrolling
> listContainer.addEventListener('scroll', () => {
>   // requestAnimationFrame guarantees calculation matches screen refresh rate (no stutter)
>   requestAnimationFrame(renderVirtualList);
> });

Yes, making the scroll event listener passive is an excellent micro-optimization for your virtual scroll engine.

To do this, pass { passive: true } as the third argument:

```ts
listContainer.addEventListener('scroll', () => {
  requestAnimationFrame(renderVirtualList);
}, { passive: true }); // Tells the browser not to wait for preventDefault()
```

Why this matters

When a browser detects a scroll event, it normally pauses execution for a brief moment to check if any JavaScript
function calls e.preventDefault() to stop the scroll action.

By setting { passive: true }, you are telling Electron's Chromium engine: "I promise I will not cancel this scroll."
This allows the native UI thread to scroll the page instantly and fluidly, completely decouples the hardware scroll layer
from your JavaScript calculation, and completely eliminates scroll stuttering on lower-end machines.

Combining it with requestAnimationFrame

Your use of requestAnimationFrame is already great because it ensures the math only runs right before the screen paints.
Adding passive: true completes the ultimate performance pairing for a high-rate scroll container.
